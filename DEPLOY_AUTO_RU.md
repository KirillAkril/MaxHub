## ⚡ ШАГ 3: Автоматический деплой через Blueprint (ОДИН КЛИК!)

### 3.1. Создать Blueprint

1. В Dashboard Render нажмите большую синюю кнопку **"New +"** (левый верхний угол)
2. В выпадающем меню выберите **"Blueprint"**

### 3.2. Подключить репозиторий

1. Render покажет список ваших GitHub репозиториев
2. Найдите репозиторий **"maxhub"** и нажмите на него
3. Если репозитория нет в списке:
   - Нажмите **"Configure account"** или **"Connect GitHub account"**
   - Разрешите доступ
   - Вернитесь и выберите репозиторий

### 3.3. Настроить Blueprint

1. Выберите **ветку** (обычно `main` или `master`)
2. Render автоматически обнаружит файл `render.yaml` в корне проекта
3. Вы увидите предварительный просмотр того, что будет создано:
   - ✅ **Web Service** (ваше приложение)
   - ✅ **PostgreSQL Database** (база данных)
   - ✅ Все переменные окружения настроены автоматически

### 3.4. Установить SECRET_KEY

**ВАЖНО:** Вам нужно установить только одну переменную вручную:

1. В разделе **"Environment Variables"** найдите `DJANGO_SECRET_KEY`
2. Нажмите на кнопку **"Generate"** рядом с полем (или введите значение вручную)
3. Чтобы сгенерировать ключ вручную, выполните на своем компьютере:
   ```bash
   python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
   ```
4. Скопируйте сгенерированную строку и вставьте в поле `DJANGO_SECRET_KEY`

### 3.5. Запустить деплой

1. Проверьте, что все выглядит правильно:
   - ✅ Создается Web Service `maxhub`
   - ✅ Создается PostgreSQL Database `maxhub-db`
   - ✅ Все переменные окружения настроены (кроме `DJANGO_SECRET_KEY`, который вы только что установили)
2. В самом низу страницы нажмите синюю кнопку **"Apply"** или **"Create Blueprint"**
3. Начнется автоматический процесс деплоя!

✅ Render создает PostgreSQL базу данных

**Это займет 5-10 минут. НЕ закрывайте страницу!**

## 👤 ШАГ 5: Создать администратора сайта

После успешного деплоя нужно создать суперпользователя:

1. Откройте ваш веб-сервис `maxhub` в Render
2. Перейдите во вкладку **"Shell"** (вверху страницы)
3. В открывшейся командной строке введите:
   ```bash
   python manage.py createsuperuser
   ```
4. Вас попросят ввести:
   - **Username:** придумайте имя (например: `admin`)
   - **Email address:** ваш email (например: `admin@example.com`)
   - **Password:** придумайте надежный пароль (минимум 8 символов)
   - **Password (again):** введите тот же пароль еще раз
5. После ввода появится сообщение "Superuser created successfully"

## ⚠️ Важные замечания

### Медиа-файлы (загруженные пользователями)

- ⚠️ На **бесплатном плане Render** медиа-файлы **удаляются** при перезапуске сервиса
- Для продакшена рекомендуется использовать AWS S3, Cloudinary или Render Disk
- Для тестирования это нормально

### База данных

- На **бесплатном плане** БД **останавливается** через 90 дней неактивности
- После первого запуска будет работать нормально
- Для продакшена рекомендуется платный план

### Переменные окружения

Все переменные настроены автоматически через `render.yaml`:
- ✅ `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT` - из БД
- ✅ `DJANGO_ALLOWED_HOSTS` - из URL сервиса
- ✅ `DJANGO_DEBUG` = `false`
- ✅ `DJANGO_SECRET_KEY` - установите вручную один раз

## 🐛 Решение проблем

### Проблема: "Bad Request (400)"

**Решение:** Проверьте переменную `DJANGO_ALLOWED_HOSTS`:
1. Откройте веб-сервис → "Environment"
2. `DJANGO_ALLOWED_HOSTS` должен содержать `*.onrender.com` или ваш конкретный домен
3. Если нет - добавьте: `*.onrender.com`
4. Нажмите "Save Changes"

### Проблема: Ошибка подключения к БД

**Решение:** 
1. Проверьте, что БД создана (статус "Available")
2. Проверьте логи веб-сервиса (вкладка "Logs")
3. Убедитесь, что оба сервиса в одном регионе

### Проблема: Статические файлы не загружаются

**Решение:**
1. Подождите 2-3 минуты (сборка статики происходит при деплое)
2. Проверьте логи на ошибки `collectstatic`
3. Убедитесь, что WhiteNoise middleware добавлен (уже есть в проекте)
